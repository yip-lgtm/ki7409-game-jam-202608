## Elevator Pitch

> 你是一隻企鵝。你叫湊企鵝。
> 你能唱出世界上所有的歌,包括不屬於你的樂隊的歌。
> 你不知道自己是企鵝,不知道 CRYCHIC 是什麼,不知道為什麼大家叫你「主唱」。
> 你只知道一件事:**有人想聽你唱歌。**
> 90 分鐘的純文字音樂懸疑劇,玩家 = 萬能主唱,選項 = 咕 / 嘎 / 咕咕嘎嘎。

## 核心設定(全劇唯一錨點)

> **「你是湊企鵝,你是誰啊?」**

### 玩家身份

- **玩家 = 湊企鵝**(社群 meme 形象)
- 一隻企鵝。短髮女生的臉在企鵝身體上
- 「神主唱」:能唱 BanG Dream 所有歌曲 + 二創改編
- 不知道自己是企鵝(玩家也不知道 —— 透過「影子的形狀」「羽毛的觸感」慢慢發現)
- 不知道 CRYCHIC / MyGO / Ave Mujica 是什麼
- 不知道「歌」是什麼 —— 她只是發出「咕」「嘎」

### 為什麼用這個設定

| 元素 | 來源 | 風險 |
| --- | --- | --- |
| 企鵝身體 | 社群 meme「湊企鵝」 | 同人低風險(通用動物形象) |
| 短髮女生的頭 | 動漫角色引用 | 同人非商用 OK |
| 咕咕嘎嘎 | bilibili 2025 二創 | 0 版權(無意義音節) |
| 短句對白 | 玩家自創 | 0 版權 |
| 歌名引用 | BanG Dream 曲名 | **合理使用**(標註出處) |
| 歌詞片段 | BanG Dream 歌詞 | **合理使用**(不超過 4 行) |
| 音頻 | **不嵌入** | 0 版權 |

### 禁止

- ❌ 高松燈這個名字(原作角色名)
- ❌ 任何 BanG Dream 角色真名(用暱稱/代號)
- ❌ 音頻文件嵌入(只放歌名 + 連結)
- ❌ 商業化(同人非商用)
- ❌ 官方立繪(用 CSS 程序化企鵝)

## Core Fantasy

> **「我是誰?為什麼大家看著我?」**
> 你不知道,但所有人在等你開口唱歌。
> 你張嘴,只發出「咕」「嘎」。
> 但她們聽到的,是她們最想聽的那首歌。

---

## Unique Hook

> **「神主唱」設定**:玩家(企鵝)能唱所有歌,但**不知道自己在唱什麼**。
> 玩家選「咕」= 唱春日影;NPC 聽到的是春日影
> 玩家選「嘎」= 唱壱雫空;NPC 聽到的是壱雫空
> 玩家選「咕咕嘎嘎」= 唱 remix;NPC 聽到的是 remix
> 玩家永遠不知道歌名 —— 但 NPC 知道,且會根據她們聽到的歌做不同反應。

### 咕咕嘎嘎的 8 首歌(全劇音樂錨點)

| 場景 | 歌名 | 樂隊 | 用途 |
| --- | --- | --- | --- |
| 解散夜 | 春日影(變奏) | CRYCHIC | 開場 |
| 後巷 | 壱雫空 | MyGO!!!!! | 玩家覺醒 |
| 屋頂 | 焚身 | Ave Mujica | 黑暗面 |
| 祥子家 | 影色舞 | Ave Mujica | 救贖 |
| Live House | 迷星叫 | MyGO!!!!! | 告別 |
| 結局 A | 栞 | MyGO!!!!! | 希望 |
| 結局 B | 名もなきもの | Ave Mujica | 接受 |
| 隱藏 | 二創曲(待選) | 二創 | 彩蛋 |

**歌名引用規則**:
- 場景 metadata 標記 `song: '春日影'`
- NPC 對話裡可以說「我聽到的是《XX》」,但**不超過 4 行歌詞**
- 不嵌入音頻,只放歌名 + 連結到 bilibili 歌單(玩家自己聽)

| Aesthetic | Priority | How We Deliver It |
| --- | --- | --- |
| **Discovery** | 1 | 「我是誰」「我為什麼在這」「為什麼我會唱所有歌」 |
| **Narrative** | 2 | 90 分鐘純文本,懸疑 + 救贖 + 告別 |
| **Fantasy** | 3 | 玩家 = 萬能主唱(神主唱設定) |
| **Fellowship** | 4 | 8 個 NPC 對玩家的反應差異化 |
| **Sensation** | 5 | CSS 程序化企鵝 + 視覺 FX |
| 其餘 | N/A | — |

### Core Mechanics

1. **打字機文本** — `setInterval` 一字一字 render,空格/Enter 加速
2. **CSS 企鵝立繪** — 純 CSS,4 種表情(neutral / shout / sad / sing)
3. **BGM 切換** — 場景觸發(本 PR 佔位,後續加免費 BGM)
4. **選項分叉 = 咕 / 嘎 / 咕咕嘎嘎**:
   - 「咕」= 選項 A 走向(較平靜)
   - 「嘎」= 選項 B 走向(較激烈)
   - 「咕咕嘎嘎」= 選項 C 走向(不確定,玩家探險)
5. **玩家對白** = 短句 + 咕咕嘎嘎(類似貓語)
6. **回憶片段** — 觸發時 UI 灰階 + 失真
7. **歌名揭示** — 玩家選完後,UI 顯示「你剛才唱的是:《XX》」(玩家才意識到自己唱了什麼)

### 不做

- ❌ Save/Load(90 分鐘不需要)
- ❌ Backlog
- ❌ 語音(同人無 CV)
- ❌ 音頻嵌入(BanG Dream 歌版權)
- ❌ 多結局(本 PR 1 路線 = 1 結局)
- ❌ 真實立繪(CSS 程序化)
- ❌ 商業元素

## Game Pillars

### Pillar 1:「神主唱 = 讀者」
> 玩家(企鵝) = 觀眾的代理人。粉絲看 BanG Dream 動畫時的感覺 = 玩家不知道自己在做什麼但被需要。
> 「我居然唱出了這首歌」= 粉絲「我居然被她/他的歌聲打動了」

### Pillar 2:「三種選項 = 三種觀眾」
> 每個關鍵選擇都有「咕 / 嘎 / 咕咕嘎嘎」三個變體。
> 咕 = 純粉(安靜追隨)
> 嘎 = 二創粉(混搭/重組)
> 咕咕嘎嘎 = meme 粉(玩梗)
> 遊戲結束後,玩家會發現「我選咕 = 純粉結局,我選嘎 = 二創粉結局」

### Pillar 3:「不知道 = 力量」
> 玩家不知道自己會唱所有歌。玩家不知道自己會改變 NPC。
> 透過 UI 提示(歌名揭示 / 角色表情變化)讓玩家**事後**發現。
> 「啊原來我這一句是春日影,難怪她愣住」。

### Anti-Pillars

- **NOT 解釋 meme**:預設觀眾懂「湊企鵝 / 咕咕嘎嘎」,不解釋
- **NOT 強行嚴肅**:meme 本身就是荒誕的,保留輕盈
- **NOT 完整解釋 CRYCHIC**:預設觀眾看過動畫
- **NOT 動畫化企鵝**:純 CSS,不能是 gif / 視頻
- **NOT 提及原作角色名**:只代號(爽世 / 祥子 / 立希 / 愛音 / 睦 / 初華 / 海鈴 / 若麥)—— 玩家在 Common Route 自己拼湊

## 場景結構(重寫)

### Common Route(30 分鐘)
- 場景:CRYCHIC 解散夜,Live House 屋頂
- 玩家 = 湊企鵝(主唱),站在舞台中央
- 8 個 NPC 圍繞
- 玩家在解散時**唱春日影(變奏)** —— 用「咕咕嘎嘎」+ 短句
- 選擇:玩家唱哪一首歌 / 對誰說話 / 留下還是飛走

### 湊企鵝(主唱)線(60 分鐘,本 PR 唯一完整路線)
- Common Route 結尾選「留下」 → 進入
- 玩家(企鵝)不知道自己為什麼能唱,開始探索
- 路上遇到 8 個 NPC 各自的崩潰時刻
- 玩家用「咕 / 嘎 / 咕咕嘎嘎」安慰 / 觸動她們
- 最終 1 結局(企鵝選擇留下或飛走)

### 其它 7 個 NPC(只出場,不開路線)
- 7 個角色作為「場景 NPC」在主唱線穿插
- 每個 NPC 1 場回憶片段(玩家觸發「咕咕嘎嘎」時)
- 不解鎖獨立路線 —— 留給後續 7 個月

## MVP Definition(本 PR 範圍)

**核心假設**:「粉絲願意花 90 分鐘玩一個企鵝主唱的迷因改編,只要音樂觸發夠精準。」

**Required for MVP**:
1. ✅ 打字機 + 選項(咕/嘎/咕咕嘎嘎)+ 場景切換
2. ✅ 繁簡切換
3. ✅ CSS 程序化企鵝立繪(4 表情)
4. ✅ 歌名揭示機制
5. ✅ Common Route 完整 5 場景(解散夜)
6. ⏳ 主唱線開場 8 場景(本 PR 寫 1-2 個,佔位其餘)
7. ⏳ 8 首歌嵌入(本 PR 用 1-2 首,佔位其餘)
8. ⏳ 標題畫面 + 通關畫面

**Explicitly NOT in MVP**:
- 音頻嵌入(永遠不做)
- 其它 7 角色獨立路線
- Save/Load
- 商業包裝
