## Elevator Pitch

> 你叫高松燈。
> 但你是一隻企鵝。
> 你站在 Live House 屋頂, 看著 8 個人準備散場。
> 你不知道「CRYCHIC」是什麼, 不知道「主唱」是什麼, 不知道為什麼大家看著你。
> 你只知道一件事:你想唱歌。
> 90 分鐘, 純文字音樂懸疑劇, 玩家 = 企鵝版高松燈。

## 核心設定

### 玩家身份

- **玩家 = 高松燈(企鵝版)**
- **人頭(高松燈的髮型 / 臉型) + 企鵝身(白肚 / 黑背 / 橙腳)**
- 不知道自己是企鵝(透過「影子的形狀」「羽毛的觸感」慢慢發現)
- 能唱所有歌(原作 + 衍生), 不知道自己在唱什麼
- 「神主唱」設定保留
- 第一人稱:文本中「你」/「高松燈」交替

## 為什麼用這個設定

- **原作粉絲熟悉度**:角色用真名, 粉絲 0 學習成本
- **企鵝立繪趣味性**:玩家立刻看出「這不是普通的高松燈」, 製造反差
- **自娛為主**:不公開發布, 0 版權壓力(同人 + 零收費 + 標註 IP 來源)
- **混合原作 + 企鵝** = 不衝突(玩家 = 企鵝 = 高松燈, 其他角色 = 原樣)

### 禁止

- ❌ 高松燈這個名字用在 NPC(只有玩家 = 高松燈)
- ❌ 音頻文件嵌入(只放歌名 + 連結)
- ❌ 商業化(同人非商用, 自娛)
- ❌ 官方立繪(用 CSS 程序化企鵝 = 高松燈髮型 + 企鵝身)

### Core Mechanics

1. **打字機文本** — 30ms/字
2. **CSS 企鵝立繪** — 4 表情(neutral / shout / sad / sing)
3. **選項 = 高松燈的內心選擇**(不是「咕 / 嘎」, 是「我該 / 我不該 / 我不知道」)
4. **玩家對白** = 第一人稱短句
5. **回憶片段** — 灰階 + 失真
6. **歌名揭示** — 0.5s 延遲, UI 顯示「你剛才唱的是:XX」

## Game Pillars

### Pillar 1:「立繪 = 設定」
> 玩家立繭 = 人頭(高松燈) + 企鵝身。這就是「如果高松燈是企鵝」的全部視覺。
> 不解釋。玩家看立繭就懂。

### Pillar 2:「名字的重量」
> 玩家 = 高松燈。其他角色叫她「高松燈」時, 是**真人**在叫一個**企鵝**的名字。
> 這種張力 = 故事核心。
> 「(吉他手 A)高松燈——你怎麼還在這?」+ 企鵝立繭 = 心碎感。

### Pillar 3:「神主唱 + 不知道」
> 玩家能唱所有歌, 但不知道自己在唱什麼。
> 透過歌名揭示, 玩家**事後**才意識到「啊原來我唱了春日影」。
> 這是原作粉絲**最有共鳴**的設計(原作裡高松燈就是靠歌聲召喚同伴的)。

### Anti-Pillars

- **NOT 咕咕嘎嘎 meme**:本次回退, 玩家不用「咕 / 嘎」說話
- **NOT 動畫化企鵝**:純 CSS / SVG
- **NOT 完整解釋 CRYCHIC**:預設觀眾看過動畫
- **NOT 強行歡樂**:保留原作沉重基調

## 場景結構(重寫)

### Common Route(20 分鐘)
- 場景:CRYCHIC 解散夜
- 玩家 = 企鵝版高松燈, 站在屋頂
- 8 個真名 NPC 圍繞
- 玩家唱春日影(變奏) → 解散 → 翌日

### 高松燈(主唱)線(60 分鐘, 本 PR 唯一完整路線)
- Common Route 結尾選「留下」
- 玩家(企鵝)探索「我是誰」
- 遇到 8 個 NPC 的崩潰時刻
- 透過歌聲觸動她們
- 結尾:玩家選擇「繼續做企鵝主唱」或「飛走回到企鵝世界」
